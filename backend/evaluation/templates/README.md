# 真实业务问题标注与人工核验模板

本目录只有**模板**，不含任何真实业务资料。`business-questions.template.jsonl` 不能直接运行，
其中的 `REPLACE-*`、中文占位符和 `verified_*` 字段都必须在真实评测前替换或删除。

> 合成样例（`cases.platform.example.jsonl` 等）只验证评测工具本身，**不代表真实业务的准确率、
> 可回答率或拒答质量**。任何对外结论都必须来自业务分层抽样并完成人工核验的真实样本。

## 1. 抽样

1. 按业务分层抽样：每个分层单独统计，不把不同难度的分层混成一个平均值。建议至少分层：
   高频事实问答、跨文档综合、流程/时效、权限与合规、明确无答案。
2. 每个分层优先覆盖真实提问中出现过的说法，保留编号、单位、时点和文档版本；不把问题改写成
   评测者熟悉的标准问法。
3. 记录抽样框和抽样数量（例如“工单系统近 90 天，按分层随机抽取”），否则可回答率无法解释。

## 2. 人工标注（每个样本必须完成）

- **人工正确性**：标注人依据原文判断“若回答为 X 则正确”，不依赖模型输出。至少一名标注人，
  关键样本建议双人独立标注，分歧由第二名或负责人裁定并记录。
- **引用支持性**：逐条核对结论句是否被所引片段原文支持；引用存在但原文不支持要点，判为不支持。
  编号/时效/单位必须与原文一致，不能从“常识”补齐。
- **可回答性**：标注 `expected_outcome`。库内确有依据为 `answer`，确无依据为 `refuse`，
  指代不明或需用户补充为 `clarify`。三类都计入分母，不得只统计能回答的样本。
- **指标口径**：可回答率 = 标注为 `answer` 且断言通过 / 全部样本；拒答正确率 = 标注为 `refuse`
  且实际拒答 / 标注为 `refuse` 的全部样本。两者都必须与分层一起报告。
- **敏感性**：记录问题、原文和回答是否含个人信息或密钥；含敏感内容的样本不得进入公开仓库，
  报告默认不得开启 `--include-content`。

## 3. 字段

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定工单号或抽样编号，禁止复用 |
| `question` | 经脱敏的真实问题；`turns` 用于多轮 |
| `expected_outcome` | `answer` / `refuse` / `clarify`，人工标注 |
| `expected_sources` | 人工核验过的来源，可含 `chunk_index`、`index_version` |
| `required_phrases` | 人工确认必须出现的原文要点 |
| `forbidden_phrases` | 人工确认绝不能出现的错误口径 |
| `stratum` | 业务分层，用于分组统计 |
| `verified_by` / `verified_at` | 核验人代号与日期，便于复核 |

模板中的 `unknowns` 仅用于标注过程；运行评测前请移到自己的人工核验表，不要混入公开样例。

## 4. 核验流程

1. 用本模板字段另存一份私有问题集（不要提交）。
2. 以 `--live` 在隔离测试部署运行，或用 `--responses` 回放已采集的私有响应。
3. 两名核验人独立判断“正确性 / 引用支持性 / 可回答性”，记录分歧。
4. 对分歧样本回到原文复核，更新标注，但在报告中保留“已核验/未核验”数量。
5. 报告业务分层结果时同时给出样本量和未核验数量；未核验样本不能计入正确率。

## 5. 与基线比较的注意事项

- 加/减业务样本会改变数据集身份，基线比较会判为 `incomparable`（退出码 4），这是预期行为：
  需要重建同数据集基线后再生效，不能在样本变化后声称“无退步”。
- 延迟与费用指标只有在全部样本都有实测值时才可用于比较；缺测会返回 `unknown`（退出码 5）。
